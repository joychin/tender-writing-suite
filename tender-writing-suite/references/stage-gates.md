# 阶段确认门（stage-gates，停轮呈现一次——答复不明即默认先行）

纪律总则：G1-G6 六道门处，产物与待确认事项**停轮完整呈现一次**（评审台/文件/
对话摘要，通道矩阵见 @references/review-workbench.md），等用户答复。答复处理：

- **明确确认 / 明确指引** → 照办，推进下一步；
- **答复但不明确**（「继续」「先这样」「你看着办」）或**只答部分** → **不追问、
  不阻塞**：未确认部分按本门声明的默认方案先行，并以注释标注待确认项；
- **纠正 / 补充** → 按用户意见办。

同一问题只问一次，不反复追问；用户随时可在评审台补改（等效确认，写台账）。

## 六道门

| 门 | 时机 | 呈现内容 | 用户未明确时的默认方案 |
|---|---|---|---|
| G1 解析确认 | 第一步概况 | 概况表 + 解析警示与需留意问题（澄清提醒前移点亮） | 按已声明的主文件/角色假设推进；纠正后重解析 |
| G2 要点与澄清 | 第二步收尾 | 关键要点 + 澄清问卷（CLAR 逐条带问题/影响/建议动作） | 已裁决照办；未裁决项照常进目录——涉及取值/承诺的位置只加批注，不把建议动作当结论写进正文 |
| G3 目录确认 | 第三步末 | 目录概要 + 清理动作 + 评审台目录 tab（树可改） | 目录按暂定稿进写作准备；用户改动落盘后增量走查回流 |
| G4 指引与提问 | 第四步.1 | 模式分布 + 缺口逐条点名 + 承诺问题清单（一次列全） | 未答项按缺料纪律批注待补，照常进承诺与正文 |
| G5 承诺拍板 | 第四步.2 | 承诺值逐条亮出；评审台承诺 tab 可填 | 未拍板的值落「待补」，正文相应位置只加 Word 批注点名，绝不编造 |
| G6 校验后合册 | 第六步 | 校验结果 + 待办批注清单 | issue 未清零也合册（清单收尾逐条点名） |

- **标注机制（未确认 ≠ 空白）**：正文与格式件用 Word 批注（comment）点名待确认/
  待补；承诺清单值列写「待补」（全局校验自动跳过待补值，不误报）；目录说明概述
  沿用「⚠待澄清：…」标记；收尾汇报把全部未确认事项逐条点名（不可只字不提）。
- **核心纪律不变**：承诺数字只出自用户拍板的清单——批注点名待拍板事项是标注
  不是写入；「不编造」凌驾于推进效率之上。失败性停止（主文件解析失败、引擎
  校验崩溃）不属于确认门，仍按各步原文处理。
- **连续模式（可选加速）**：用户明确授权「自动跑完/不用每步问我」后，各门降级为
  呈现后不停轮直接推进（默认方案与批注标注照旧）；未授权不走此档。

## 台账（work/decisions.json）

记录**用户**的确认与裁决（对话答复或评审台按钮）：
`{"gates": [{"gate": "G3", "verdict": "pass", "note": "", "at": "..."}],
"clarifications": {"CLAR-01": {"verdict": "...", "note": "...", "at": "..."}}}`。
向用户提及时说「你的确认记录」；agent 按默认方案的推进决定不写台账。
