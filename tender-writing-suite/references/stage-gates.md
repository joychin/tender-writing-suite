# 阶段确认门（stage-gates，关键产出必须过人才能往下走）

纪律总则：**G1-G6 六道门处，产物没过用户的眼就不进下一步**；「停轮等确认」是默认
语义，只有用户明确授权连续模式才降级。门的呈现走对话内结构化清单（主问题+要点+
唯一主要动作），需要用户动手改的产物同时按展示通道打开评审台（见
@references/review-workbench.md）。每道门通过后把结论写进 `work/decisions.json`
（门、结论、时间），续跑或重开会话时已过门直接沿用、**不重复问**。

## 六道门

| 门 | 时机 | 呈现给用户 | 通过动作 |
|---|---|---|---|
| G1 解析确认 | 第一步概况确认 | 概况表 + **解析警示与需留意问题**（扫描件/无大纲/表格失真/同名文件——待澄清事项在这里先亮出来提醒） | 回复确认；或指出问题重新解析 |
| G2 要点与澄清 | 第二步收尾 | 关键要点（废标最严几条/评分框架/资格硬门槛）+ **澄清问卷**（CLAR-xx 逐条：问题/影响/建议动作，等裁决） | 逐条裁决或回复确认 |
| G3 目录确认 | 第三步末 | 目录概要 + 清理动作 + 打开评审台目录 tab（树可改） | 确认；或在评审台改完再确认 |
| G4 指引与提问 | 第四步.1 停轮汇报 | 模式分布 + 缺口逐条点名 + 承诺问题清单（一次答全） | 答复清单 |
| G5 承诺拍板 | 第四步.2 承诺值汇报 | 承诺值逐条亮出；评审台承诺 tab 可填 | 明确拍板；**永不免检** |
| G6 校验后合册 | 第六步校验后 | 校验结果 + 待办批注清单，确认后才 assemble | 确认合册 |

- G2 的澄清问卷与 G4/G5 的提问若用户未逐条答复，缺项按「待补」落清单、正文走批注，
  **不编造、不替用户拍板**；
- 评审台各 tab 的「标记通过」「记录裁决」按钮等效于对话确认（写同一台账）；
- G3 之后用户在评审台改了目录 → 改动即刻生效，但要把 apply 的 diff 报告与下游旗标
  （被删节点的指引行、新叶子缺指引行）逐条向用户点名，并提示重过 G3。

## 连续模式（免检授权）

- **启用条件**：用户明确说「自动跑完」「不用每步确认」这类话才启用；含糊表述
  （「快点」「简单弄弄」）不算授权，判断不了就问一句；
- **降级语义**：G1-G4、G6 改为**越门汇报**——不停轮，每道门发一段结构化摘要
  （做了什么、跳过了哪道确认、哪里可以在评审台事后改），继续往下走；
- **永不免检（两条硬门）**：
  1. **G5 承诺拍板**——没有用户给过的值不写任何承诺，写到 G5 必须停下等拍板；
  2. **响应文件拆分歧义**——拆分有多种合理方案时停下问用户（拆错了整本返工）；
- 越门汇报的摘要不省略：待澄清未裁决、缺口未给值、批注数在收尾汇报里逐条点名。

## 台账（work/decisions.json）

机器维护、用户可读：`{"gates": [{"gate": "G3", "verdict": "pass", "note": "", "at": "..."}],
"clarifications": {"CLAR-01": {"verdict": "...", "note": "...", "at": "..."}}}`。向用户
提及时说「你的确认记录」。评审台按钮与对话确认都写这里；连续模式的越门汇报**不写
pass**（那不是用户过的门），只在对话里汇报。
