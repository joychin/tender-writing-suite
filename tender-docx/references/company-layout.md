# 公司版式：读取、确认、登记与自动采用

用户给一份 Word 版历史标书、说「以后都按这个样式来做」时，走三步：**读取**（layout-read
把它的版式读成一张版式规格表）→ **确认**（取值由用户过目）→ **登记**（layout-adopt）。
规格表是公司版式的本体：登记之后，建节、合册不指定模板就自动按它出；改版式就是改这张表。

用户只通过对话表达意图——模板、参数、命令都由你消化，不甩给用户（2026-11-27 真机：
套件到读出规格表就停了，模型让用户「建节和合册时传入这个参数」，这句话不该出现；
也不替用户手工写脚本搭模板）。

```bash
python3 tender-docx/scripts/docx_toolkit.py layout-read "历史标书.docx" --out work/版式规格.md
python3 tender-docx/scripts/docx_toolkit.py layout-adopt work/版式规格.md --source "历史标书.docx"
python3 tender-docx/scripts/docx_toolkit.py layout-adopt <登记目录>/layout.md --set "标题一级=中文黑体、西文 Times New Roman｜三号（16 磅）｜加粗｜居中"
python3 tender-docx/scripts/docx_toolkit.py layout-show
python3 tender-docx/scripts/docx_toolkit.py layout-forget
```

读取全程只读：不改被读取的文件；原件不复制（历史标书里有价格与人名），只在规格表来源行
记文件名与指纹。`--out` / `--json` 后面跟的是结果落盘路径（`.md` / `.json`），不是开关；
要读的文件跟在 `layout-read` 后面——路径落到被读取的文件上或后缀不对会被拒绝，什么都不写。

## 输入口径

- 只收 `.docx` / `.doc`。PDF、图片读不准字体与磅值，工具直接拒绝，请用户给 Word 版。
- `.doc` 先转成 docx 后读取：本机有 LibreOffice 脚本自动转（回显一行转换说明）；没有时
  脚本列出检测到的 Office 套件后退出（退出码 2），由你选本机可用的办法转成 `.docx`，再对
  那份 `.docx` 重跑同一条命令——LibreOffice 不是前提，不要一上来就让用户安装。
- **超过 5MB 的 `.doc` 脚本不自动转**（LibreOffice 转大文件可能很久都转不完）：直接退出
  （退出码 2），请用户在 Word/WPS 里另存为 `.docx`，这一步不要替用户自动化；转好后对那份
  `.docx` 重跑同一条命令。
- **LibreOffice 转换超时（超过 300 秒）或失败时同一个出口**：脚本先把转换进程终止掉再退出
  （退出码 2），同样请用户在 Word/WPS 里另存，不要另想办法转。转不出来的多半是个别图片／
  绘图对象的数据不规范，与文件大小无关。
- 转换只能用真正的 Office 另存（Word / WPS / Pages / LibreOffice）。**把文字抽出来重新
  拼成 docx 不算转换**——表格、样式、页面设置全丢，读出来的是一堆缺省值（真机上转一份
  26MB 的 .doc 超了时，模型自己拼了一份：17.9 万段纯文本、一张表都没有）。
- 文件不存在、格式不收都是一行中文提示，不抛报错栈。

## 触发、确认与登记

- 用户明说「按这个样式做」「这是我们公司的标准」「以后都按这个样式」才读版式并登记。
  只说「这是历史标书」是给素材，读文字不读版式——同一份文件两种角色，只有用户能说是哪种。
- 单独触发：读完当轮把规格表交给用户，不为它单独停轮；项目流程里触发：规格表随当轮的
  确认面一并给出。
- **确认**：读得准的照报；几种写法并存的（表里标「疑似」的行）点名请用户挑，用户没说就按
  排在前面的出。疑似项一次问清，不反复追问；「未发现」只对末行写的已检查范围成立。
- **登记**：用户点头后跑 `layout-adopt`。回显五行照实转告——生效的项；需要用户看一眼的项
  （并存的几种，已按排在前面的出）；这一版还没接上的项；字体提醒（macOS 自带字体在
  Windows 上会回退，把登记表里的字体名改成出稿机器上有的再登记一次）；末行「对用户怎么说」
  可以直接用。
- 登记目录在用户主目录下 `~/.lingyan/tender-layout/`（环境变量 `TENDER_LAYOUT_HOME` 可改），
  两个宿主共用同一份登记——说一次就够。里面：`layout.md`（规格表本体）、`layout.json`
  （解析结果与资产清单）、`封面.docx` 与 `媒体/`（带 `--source` 登记时从历史标书里提取的
  公司封面与页眉 logo）、`历史/`（换版式、取消登记时的留档）。
- **`--source` 要带上**：封面整页与页眉（logo／文字／横线）要从历史标书里取件，登记时把
  那份文件一起给（`--source`，与规格表读自同一份）。不带时封面与页眉列进「还没接上」，
  回显会写明重登一次就能接上。
- **读出什么报什么**：取值由用户确认。看着不合习惯的读数——标题跟正文同为宋体小四
  不加粗、目录缩进打在条目文字里——也是用户公司的版式，照报并带上依据列的样本数；
  不替用户改良、不推荐「更好看」的写法。
  一份技术标全篇统一字体字号，常常是照着招标的格式要求有意做的。
- 优先级不变：招标文件给了格式件、封面样例、明文排版要求的，按招标的来；公司版式
  只落在招标没规定的项上。
- 回显末尾两行（`[下一步]`、`[取值]`）就是上面这几条，照着执行。

## 自动采用的口径

登记后建节、合册不指定模板就自动按公司版式出，回显首行 `[版式]` 点名用的是哪份。
跟版式走的项：

| 版式里的项 | 出稿时落在哪 |
|---|---|
| 纸张、页边距、装订线、文档网格、对称页边距 | 页面设置（横向节、前置节沿用同一组边距） |
| 正文字体、字号、行距、段前段后、缩进、对齐 | 正文样式与逐段的首行缩进 |
| 一至四级标题（字体字号加粗对齐、间距） | 标题样式（链接的字符样式同步） |
| 目录标题、各级条目、行距与段距、逐级缩进、点线、层级 | 目录页；页码制表位落在版心右缘 |
| 编号形态、编号与标题的间隔、章起新页 | 合册的编号；首章前一律分页 |
| 表格边框、表头样式、表格文字、单元格边距 | 自建表（招标格式件照旧只拷不改） |
| 表题、图题 | 表题样式与图题样式各按各的；表题在表上方还是下方也跟版式 |
| 页码写法、位置、字号 | 页脚或页眉；口径不变——封面、前置页、目录页不编号，正文从第 1 页起 |
| 图宽 | 按登记的「占版心比例」缩放 |
| 封面整页 | 目录树有「封面」节点且没写封面节文件时，落登记的公司封面为 body/封面.docx 并合入；里面的项目名、投标人、日期还是历史标书上的，合册回显点名字段清单，开写时先改 |
| 页眉 | 正文节页眉：logo 图（按登记的原尺寸）＋文字＋横线；封面、前置页、目录页不带 |

- 历史标书里没有的项（未发现表格、未见表题、没有目录）按内置写法出，不算「跟版式」。
- 模板每次出稿时从当前的内置基准模板现编译：引擎升级后登记的版式不会卡在旧模板上。
- 登记之前建的节文件，合册时同样按登记的版式出（同名样式以整本的为准）；节文件里表格
  字号这类直写格式还是建节时的样子，要完全跟版式就重建那些节。
- **用户或招标文件明说了的优先**：`--numbering`、`--toc-depth`、`--template` 明给就按明
  给的；用户说「这份不按公司版式」，建节、合册加 `--ignore-layout`。

## 对话修订

- 用户说「标题改成黑体三号加粗」「页码改成居中」这类：`layout-adopt <登记目录>/layout.md
  --set "项目=取值"`。项目名用规格表「项目」列的原词，取值写法跟规格表一致（字号带磅值
  或用字号名，字体写成「中文黑体、西文 Times New Roman」，格式各段用全角竖线隔）。写错会被
  拒收（退出码 2）并给出这个项目的写法样例；项目名写错会列出可改的项目。
- 直接改登记目录里的 `layout.md` 也行：下一次出稿按改后的表读，并回显一句。改坏了（有一行
  读不出来）就沿用上一次读得出来的取值出稿，回显点名哪一行——修正后重跑 `layout-adopt`。
- 修订后回显「对话修订已记入：项目名」，转告用户时说「已改，后面新写的标书按改后的来」。

## 用户问、用户说

| 用户的话 | 做什么 |
|---|---|
| 「以后都按这个样式」＋一份 Word 版历史标书 | 读取 → 给表确认 → 用户点头后登记 |
| 「现在用的什么版式」「我们公司版式是什么」 | `layout-show`，把表转述给用户 |
| 「标题改成……」「页码改成……」 | `layout-adopt … --set`（见上） |
| 「这次不用公司版式」 | 建节、合册加 `--ignore-layout` |
| 「别用公司版式了」 | `layout-forget`（原规格表留档，可恢复） |
| 「换一份样式」 | 对新的历史标书走读取 → 确认 → 登记（上一份留档） |

## 这一版还没接上的

登记时回显会点名，转告用户时照说，不许含糊成「都按这个样式」：

- **表格列宽**：列宽仍由引擎按内容分配（单元格边距跟版式走；招标给了列宽的格式件照旧只拷不改）。
- 封面页沿用正文页边距——公司封面自带绝对定位的文本框、页边距又与正文不同时会有挪位；
  出样张看图确认，不行就把封面页边距也接上（下一小批）。

## 读法与确定／疑似

- **机器读**：整份文档只有一种取法（纸张、页边距、文档网格、页码域），直接采信。
- **看一眼**：可能混着当年招标要求的格式或拷来的素材（正文、标题、表格、题注）。
  逐段算生效格式后取多数，请用户过目。
- **对话定**：机器分不清意图的（封面哪些字每本要换、页眉里的项目名），只给候选。

取多数的规则（**经验值**，手头只有两份真实文档，样本多了要复核）：只有一种取值记
「确定」；有两种以上并存时，最高占比过了 75% 才记「确定」，否则记「疑似」并把前
三种并列进取值。只看占比不看样本量——1/1 也记确定，样本数写在依据列里，读表的人
自己判断。

读数一律按**生效格式**算：直写 → 样式链 → 文档默认 → 主题。真实历史标书常把字体
100% 直写在文字上、样式表里定义上百个样式却一个标题样式都不用，只看样式表会读错。

文档不规整时不崩，读得出的照读、读不出的照实标：

- **没有一级标题**（小册子常把章挂在「标题 2」上；经验值：手头 12 份真实标书里 4 份
  如此）：「章起新页」退到最浅的一级读，依据写明「没识别出一级标题」并记疑似。
- **节里没写纸张或页边距**（别的转换器转出来的 docx 常这样）：按 Word 缺省值读出，依据
  注明「取的是 Word 缺省值」并记疑似；文档连节属性都没有时整份按一节、缺省值读。
- **某一组读不出来**：那一组在表里留一行「本组读取中断」或「本组未读」（写明原因），
  首行点明有几项没能读取，其余各组照读——把这一行原样反馈，不据此下结论。
- **首行后紧跟 `[注意]`**（文件里一个样式都没有）：这份文件当不了版式样本，多半是把
  文字抽出来重新拼成的，不是 Office 另存出来的——请用户另存原文件后重读。

**认不出的章标题**：章标题挂「正文样式 + 自动编号」（编号是「第%1章」这种域，不在
文字里）时进不了标题候选，标题组会缺「标题一级」那一行——依据里看到「没识别出一级
标题」而文档明明有章时就是这种情况，如实告诉用户这一项没读到。

## 读取清单

| 组 | 读什么 | 怎么读 |
|---|---|---|
| 页面 | 纸张、页边距与装订线（**取正文所在那一节**，不按封面节）、各节页面设置差异、对称页边距、文档网格（按类型：无网格／行网格／行和字符网格）、页眉（文字、字号、对齐、横线、logo、首页不同、奇偶页不同，逐节读）、页码写法与位置（以正文所在节为准，其它节不同时点名）、页脚其他文字 | 机器读 |
| 正文 | 中文字体与西文字体（两套）、字号、行距、段前段后（磅、行、自动三种写法；样式链上都没设时取文档默认值——段后 10 磅常写在那里）、缩进、对齐（没设就是左对齐）、中文版式（避头尾、标点溢出、中西文间距等，逐段走样式链）、列表习惯与空行习惯（只记不落） | 看一眼 |
| 目录 | 「目录」标题格式、各级条目的字体字号加粗、目录层级、行距、段前段后、逐级缩进（含打在条目文字里的全角空格）、引导线 | 机器读 |
| 标题 | 一至四级与「五级及以上」各自的字体字号加粗对齐、间距、编号形态、编号与文字的间隔、每章是否另起页、用到几级 | 看一眼 |
| 表格 | 边框（直接设置与表格样式都解析）、表头底纹加粗对齐、单元格文字、表宽、单元格边距、行不跨页与表头跨页重复、表题（位置、格式、编号写法） | 看一眼 |
| 图 | 图题（位置、格式、编号写法）、图宽与占版心的比例 | 看一眼 |
| 封面 | 整页清点（文字行、表格、图、文本框）、逐行标记像会变的字、封面页设置与正文是否相同 | 对话定 |

区域划分：封面=首页（到第一个分页或分节符为止）；目录区=「目录」标题到末条目录
条目，条目认五种形态（toc 样式、页码引用域、点线页码、制表符加页码、标题后的纯
文字条目）；封面与目录之间的前置页（如评分索引表）单列。三个区都不进正文统计，
表格和图也只统计正文区的。

标题候选有两种来源：命名标题样式；或自带编号的短段（不超过 40 字，不以句末标点
收尾，加粗或不超过 20 字——手打编号的条款行不算标题）。

**不读**：文档属性（建稿时统一清空，匿名评审用）、标题颜色、脚注尾注、水印、页面
边框、分栏、列表缩进细节。它们列在输出末行的「未读」里。

## 版式规格表长什么样

`--out` 落盘的就是这个形态（四列固定：项目｜取值｜依据｜确定/疑似，逐组一张表）：

```markdown
# 版式规格

> 来源：公司标书.docx（sha256 3f9a12b7c05d…）；读取时间 2026-11-26 10:20。
> 本表是公司版式的本体：取值可直接改，「确定/疑似」列是机器读数的把握程度，「依据」列写着样本数。……

【页面】
| 项目 | 取值 | 依据 | 确定/疑似 |
|---|---|---|---|
| 纸张 | A4 纵向 | 正文所在第 5 节，21×29.7 厘米 | 确定 |
| 页边距 | 上 3、下 2.54、左 2.6、右 2.4 厘米 | 正文所在第 5 节 | 确定 |
| 页面设置差异 | 第 1 节：上 2.54、左 3.17、右 3.17；第 2–4 节：上 2.54、左 1.9、右 1.9（与正文节不同） | 共 5 节，逐节比对纸张与页边距 | 确定 |
| 页码写法 | 第 X 页、页脚居中｜小四（12 磅）（第 3 节页脚左） | 页码域（正文所在第 5 节；第 3 节起才有，第 1–2 节无） | 确定 |

【正文】
| 项目 | 取值 | 依据 | 确定/疑似 |
|---|---|---|---|
| 正文字体 | 中文Songti SC、西文 Times New Roman | 正文候选 595/600（99.2%） | 确定 |
| 对齐 | 左 ／ 两端 ／ 居中 | 正文候选 446/600（74.3%），3 种并存 | 疑似 |

（目录、标题、表格、图、封面各组同形）
```

取值写法固定：字体 `中文仿宋、西文 Times New Roman`、字号 `五号（10.5 磅）`、
行距 `1.2 倍`／`固定 22 磅`／`单倍`、缩进 `首行 2 字`／`无`、页边距
`上 2.54、下 2.54、左 3.18、右 3.18 厘米`。登记时（`layout-adopt`）按这份写法解析，
`--set` 改取值时保持既有写法。

## 判读时注意

- **依据列先看**：`10/14（71.4%）` 说明这一项只有 14 个样本、七成多是一种格式，
  即使占比高也要结合样本数看。
- **疑似项不阻塞**：按排在最前的取值理解，向用户点名请其定夺；取值里并列的就是
  文档里实际并存的几种。
- **封面文字**：`→` 是像会变的字（机器按日期、编号、项目名称、供应商等线索标的，
  只是候选）。带 `--source` 登记后这些字段随公司封面一起落到每本标书的封面节文件里，
  开写时按这份标记改成当前项目的值；`·` 是看着固定的文字，不动。
- **事实行**写明命名标题样式用了多少段；一段都没挂时写明外观是全写在文字上、取自正文
  默认样式、还是两者混着（三种情形读数都按生效格式算）——这句话是量出来的，转述时照抄。
- 对话里给用户讲这张表时按 reply-style 的口径：内部说法「确定／疑似」说成
  「读得准／需要你看一眼」，脚本名与子命令名不出口。
