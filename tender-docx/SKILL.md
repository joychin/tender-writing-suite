# 合册与交付（第七步）

开始前先载入入口技能 tender-writing-suite：红线与门行为以它为准；本文件只讲
合册与交付。环境依赖与工作目录约定同在入口技能。

## 上游检查

`work/body/<节>.docx`、`work/body/写作指引.md`、`work/body/关键事实与承诺.md`
是合册输入；节未全部完成 → 载入 tender-writing 回到第五步。`work/review/`
评审台与 G6 校验结果应在合册前刷新过（见 @tender-writing-suite/references/stage-gates.md
G6 条）。

## 第七步：合册整本

```bash
python3 tender-docx/scripts/docx_toolkit.py assemble --work work
python3 tender-docx/scripts/docx_toolkit.py toc-pages "work/body/整本-投标文件.docx" --pdf work/导出/预览.pdf --map work/pagemap.json
python3 tender-docx/scripts/docx_toolkit.py inspect --work work     # 整本检查（只读）：页码回填后跑，结果随收尾汇报交给用户
```

`--numbering`、`--toc-depth` 缺省跟登记的公司版式（没登记用 chapter 与 3 级）——
招标文件对编号、目录层级有要求时才明给，方案说明见 `--help`；`--flat-outline` 把节内
小标题摘出导航窗格（导航降噪用，
默认关——开了 F9 刷目录会丢二级以下条目）。`--map` 导出「标题→页码」JSON 供
评分索引表等机械回填。**页码口径**（常规做法，招标文件另有要求时按招标的来）：封面/前置/目录不编页码，正文分节
自第 1 页起编。**整本是派生产物**：编号与目录页由合册机械生成、待办批注原样
迁移；改内容回节文件层改再合册（直接手改整本会被覆盖）；返回的警告逐条点名。

**合册前先核对招标格式件**：节内表格与原件格式表对不上（列数变了、原件标签丢了、
整张表没了）即拒绝合册——擅自改格式件是废标级红线（入口红线 8）；用户在对话里
明确同意改结构的节，加 `--allow-format-change "<节名>"`（多个用逗号分隔）放行。

`toc-pages` 是**实测→回填→复测**（默认至多 5 轮，`--max-rounds` 调）：
回填会改目录占行、正文跟着再漂，两轮实测一致才算完成；没收敛就整体回滚、不
写出错页码，并明确告诉用户本轮页码没测稳。收敛后顺带核对表格里「第X章」交叉引用（只报事实，章号写错或
章节增删未同步会被点名）。

**终稿字体固化（合册固定执行）**：theme 东亚字形补显式 + 样式层归一 + run 级
剥主题字体属性并固化 eastAsia——模板会被 skill 更新覆盖、拷入的历史标书 run 里
主题字体属性会顶掉显式设置，合册收尾统一固化，字体不一致不出现在交付稿里；回显 `[字体固化]` 一行。

版式：缺省用登记的公司版式（没登记用内置基准模板 `templates/base-template.docx`），
建节与合册回显 `[版式]` 一行点名用的是哪份。用户明说用某份模板才传 `--template`，
模板里的样式与
页面设置原样沿用。模板缺 Normal／Heading 1-4 时脚本按内置样式补建并回显
`[模板标题样式]`——那几级标题是黑体、不跟模板走；用户要按公司样式，请先在模板里定义
这些标题样式（历史标书多是字体直写、没有标题样式，直接拿来当模板就是这个情形）。
需重建模板时跑
`python3 tender-docx/scripts/make_template.py`。中文字体链路起建时自动归一；
用户模板带日文主题语言时建节回显 `[模板中文字体]` 一行，用户报「标题字体不对」
先看它。

## 版式与图片工具

- **页数压缩** `compact --docx <file> [--line-pt 22]`：正文段固定行距（exact）。
  大字号段（字号×1.2 超行距）、含图段、目录段保护常开不可关——exact 行距会把
  36pt 封面标题压扁、图片裁成一条，靠保护跳过而非事后补救。表格与页眉页脚不动。
- **图片方向核对** `image-scan --docx <file>`：导出全部内嵌图片的缩略图网格
  （带序号），人眼扫一遍核方向——证件方向自动判定不可靠；发现错向记序号，
  `image-rotate --docx <file> --index N --deg 90|180|270` 就地旋转（自动按新
  比例重算引用处 extent，不会拉伸变形）。

## 文档检查（只读）

检查只负责发现：不改被检查的文件、不拦流程。输出是一行结论加一张表（位置、问题、依据、
确定还是疑似），用户要求修订时才动文件。

```bash
python3 tender-docx/scripts/docx_toolkit.py inspect --work work                  # 整本检查：整本自身 + 整本与节文件的对账
python3 tender-docx/scripts/docx_toolkit.py inspect "标书.docx" "报价表.docx" --json work/review/inspect-result.json
                                                                                # 单独检查一份或几份 Word（多份时各处写的总价互相对账）
```

- **`--json` 是落盘路径，不是开关**：后面跟一个 `.json` 路径，把检查结果写成文件（不给
  就只打印、不写任何文件）；要检查的 Word 文件跟在 `inspect` 后面，别跟在 `--json`
  后面——路径落到被检查的文件上或后缀不对，工具直接拒绝、什么都不写。
- **金额验算**：单价 × 数量 = 合价、合计 = 明细之和（多级小计逐级）、大写 = 小写、
  各处总价一致、税额 = 金额 × 税率；读不出的格、空着的格、认出是报价表却没有一行能
  验算的都会点名——不声不响地没查比误报更危险。
- **其余各项**：内部对账编号外泄、没替换的占位写法与贴入位、表格超出可用宽度／窄列／
  固定行高、图片拉伸／超宽／损坏、行距比字小、域报错、未接受的修订、文档属性里的
  工具痕迹（含 WPS 的 ICV 等自定义属性）、首页缩略图残留、看不见的批注残留。
  引擎所有落盘（建节/修订/批注/合册/压缩等）都会自动把元数据清零——用户问「交付稿
  会不会带我们的名字」时答：套件自己生成的部分不带，外部文件带进来的痕迹以检查表
  为准，要不要清由用户定。
- **整本对账**（`--work`）：节文件比整本新（整本没重新生成）、整本被手工改过（重新
  生成会覆盖）、批注数与各节之和对不上。
- **读表**：确定的排前面，疑似（列宽折行、分辨率这类靠估算的）要人看一眼；同类版式
  问题在同一份文件里满 3 处并成一行（逐处位置在 `--json` 结果里）；「未发现」只对
  最后一行写的已检查范围成立。属于招标格式件的版式问题表不能改，提示用户手动处理。

## 公司版式（按用户公司的样式出稿）

用户给一份 Word 版历史标书、说「以后都按这个样式」时，走**读取 → 确认 → 登记**三步。
登记之后建节、合册不用指定模板，自动按公司版式出——用户只通过对话表达意图，模板与
参数由你处理，不让用户碰（也不替用户手工写脚本搭模板）。

```bash
python3 tender-docx/scripts/docx_toolkit.py layout-read "历史标书.docx" --out work/版式规格.md
python3 tender-docx/scripts/docx_toolkit.py layout-adopt work/版式规格.md --source "历史标书.docx"   # 用户点头后登记
python3 tender-docx/scripts/docx_toolkit.py layout-show                      # 「现在用的什么版式」
python3 tender-docx/scripts/docx_toolkit.py layout-forget                    # 「别用公司版式了」
```

- **读取**（只读，不改被读取的文件；原件不复制——历史标书里有价格与人名）。
  `--out` / `--json` 是落盘路径，不是开关。
- **触发**：用户明说「按这个样式做」「这是我们公司的标准」才读；只说「这是历史
  标书」是给素材，读文字不读版式。
- **只收 .docx/.doc**：PDF 读不准字体与磅值，请用户给 Word 版；`.doc` 先转成 `.docx`
  再读——5MB 以内本机有 LibreOffice 脚本自动转（超时或失败时脚本会终止转换并退出，同样请用户
  另存），没有就由你选本机可用的办法转换；**超过
  5MB 的 `.doc` 脚本不自动转**，直接请用户在 Word/WPS 里另存，这一步不要替用户自动化。
  转好后都对那份 `.docx` 重跑同一条命令（LibreOffice 体积大，不要一上来就让用户安装）。
  转换只能用真正的
  Office 另存，**把文字抽出来重新拼成 docx 不算转换**（表格与版式全丢）；文档不规整时
  读不出的项会标成「读取中断」或紧跟一行 `[注意]`，照实转达，别拿缺省值当公司版式。
- **输出**：一行结论 + 分组规格表（项目｜取值｜依据｜确定/疑似）+ 事实行 + 封面
  文字逐行标记（→ = 像会变的字）+ 已检查范围（含未读项）。「依据」列写着样本数，
  转述时带上。读数按生效格式（直写→样式链→文档默认→主题），页边距与页码取正文所在节。
- **确认**：把表交给用户过目——读得准的照报，几种写法并存的（表里标「疑似」的）点名
  请用户挑，用户没说就按排在前面的出。
- **登记**：用户点头后跑 `layout-adopt`，**带上 `--source` 那份历史标书**——封面整页与
  页眉（logo／文字／横线）要从里面取件，不带则这两项先「还没接上」（回显写明重登一次就能接）。
  规格表就是公司版式的本体，存在用户目录下；
  回显列着生效的项、需要看一眼的项、这一版还没接上的项（没带源时是封面与页眉，带了只剩
  表格列宽），照实转告，末行「对用户怎么说」可以直接用。登记前出稿按内置版式，登记后自动采用；
  招标文件给了格式件、封面样例、明文排版要求的仍按招标的来——编号、目录层级用
  `--numbering`、`--toc-depth` 明给。
- **对话修订**：用户说「标题改成黑体三号加粗」这类，用
  `layout-adopt <登记目录>/layout.md --set "标题一级=中文黑体、西文 Times New Roman｜三号（16 磅）｜加粗｜居中"`，
  取值写法跟规格表一致，写错会被拒收并给出这个项目的写法样例；直接改登记的规格表也行，
  下一次出稿按改后的表读。
- **这次不用**：用户说这份不按公司版式，建节、合册加 `--ignore-layout`；用户明说用
  某份模板才传 `--template`（传了就不按公司版式）。
- **读出什么报什么**：取值由用户确认。标题跟正文同形、目录缩进打在文字里这类看着
  不合习惯的读数，也是用户公司的版式，照报并带上依据列的样本数；不替用户改良、
  不推荐「更好看」的写法。回显末尾的 `[下一步]`、`[取值]` 两行就是这几条纪律。
- 细则（读取清单、规格表示例、确定线、判读注意、登记目录与还没接上的项）：
  @references/company-layout.md。

## 人工修改与回流

节文件、写作指引、关键事实与承诺、目录树都是**普通文件**，可任意编辑器直改；
**评审页面是推荐的修改入口**（`tender-review/scripts/serve_review.py` 起服务后
页面直改，保存落盘出 diff 报告，规程见
@tender-review/references/review-workbench.md）。回流规则：改了节 .docx →
重新 `assemble`；改了目录树 → 重新 `assemble`（缺失节会被点名）；改指引/承诺 →
重跑 `tender-writing/scripts/check_writing.py` 对账。

**修改入口口径与停服务联动**：本地服务收尾即 `--stop` 关停，停后评审页面链接
失效——交付/收尾消息里修改与批注销号的入口只写 Word 批注（批注在文档里，不
依赖服务）；用户想用页面改，给离线文件路径（`work/review/评审台.html` 浏览器
直接打开）或重起服务命令——已停服务的链接别再当可用入口发给用户。

## 收尾汇报

- 各节完成情况、未写节及原因、整本 Word 文档路径（响应文件构成有几册就几个
  文件）——**对话口径=整本 Word 文档，不说「合册」**（reply-style 硬规则 9）；
- **待办批注逐条点名**（缺什么/要用户定什么）；素材异议点名（节名 + 不符点 +
  建议）；图示计划 vs 实际产出对账；
- **文档检查表**：把 `inspect --work` 的表原样贴给用户（金额、版式、批注对账这几类），
  说明本次只读、未改文件，请用户定哪些要修——用户说修才回节文件改、重新生成整本；
- **沉淀建议**（口径见 @tender-writing-suite/references/reply-style.md，只列
  清单不擅动库）；
- **导出提醒（必报）**：交付 PDF 用 Word/WPS 导出（目录域自动刷新）；
  LibreOffice 导出的 PDF 宋体被换黑体，只作内部预览。
- **不自动生成 PDF 交付稿**：终稿前通常还要人工调整，PDF 由用户定稿后
  从 Word/WPS 导出；`toc-pages --pdf` 的预览 PDF 仅内部测页码用，不作
  交付物主动提供。

## 链尾

交付完成，无下一环。用户提出改正文，或要求修订文档检查表里的某处 → 回
tender-writing 写作环节改节文件后重新合册（招标格式件的版式问题除外：表不能改，
提示用户手动处理）。
