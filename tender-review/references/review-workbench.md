# 评审工作台（review-workbench：G3 起唯一确认面——总览/目录树/写作指引/承诺清单）

评审台是一个自包含 HTML 页面（零外部依赖），装四个 tab：总览（「需要你确认的
事」待办卡 + 招标文件分析报告入口卡——分析明细不在本页，全量在报告页）、
目录树（可编辑）、写作指引（左树右详情）、承诺清单（拍板卡）。**首建于 G3
（目录确认）**——分析阶段（G1/G2）不产评审台，交付面只有分析报告页；此后
所有确认动作（拍板/树与指引编辑）都在页面做，保存后由本地服务直写 work/
产物——改的就是 agent 后续读的那份 md。
**对话只做指针**：每道门刷新页面、锚到对应区，对话文本=一行结论+待办去向一句话
（+至多 3 条标题级提醒），逐条清单不进对话（门锚点矩阵见 @tender-writing-suite/references/stage-gates.md）。

## 分析报告页（只读展示产物，分析内容唯一呈现面）

`build_review.py` 产出 `work/review/招标文件分析报告.html`——纸感公文体、零交互
零按钮、单文件自包含（可转发可打印）。**交付时机：单轮体检出表后、G1 与 G2**
——分析阶段「看分析」交给用户的就是它，也是该阶段唯一交付面（宿主有内联
HTML/附件展示能力即作为产物呈现，否则给文件引用；打印/转发场景直接用文件）；
报告页不承载任何确认控件——澄清处理、目录确认等确认动作分别在对话与评审台
（G3 起）进行，报告页不构成第二确认通道。内容 = work/analysis/ 六张登记表全量
（来源与项目概况/结构要求/商务技术要求/评分/废标/澄清，各带覆盖范围声明），
与评审台同一份 payload，零分叉。

**两页互链（相对路径，file:// 与服务模式行为一致）**：评审台总览「打开报告
页面」入口 → 报告页；报告页脚「回到标书评审台」回链 → 评审台。服务模式路由
`/<token>/report.html`（实时渲染报告）与 `/<token>/评审台.html`（评审台别名，
报告页回链落在它上面）；静态模式两文件同目录，相对链接直接可用。报告在评审台
生成前（G1/G2）页脚是纯文字指引，G3 起重刷报告自动带上回链；互链是增强非依赖
——报告单独转发时回链失效，不影响阅读与打印。

## 写作进度面板（监视面，G3 起随全量生成、第五步首开）

`build_review.py --pages all` 在目录已定时另产 `work/review/写作进度.html`——
**监视面不是确认面**：零交互零按钮，不承载任何确认控件（拍板/树与指引编辑仍在
评审台），只呈现写作阶段的过程状态与收尾交付检查。**首次打开=第五步第一节开写前**
（有打开类工具即打开，否则 Markdown 链接；打开后当轮照常停轮起手第一节前不需
再停——面板是背景监视，不构成门）。五区内容：进度总览（已写 N/M 节·分册进度条·
批注/待拍板/校验 issue 四数字卡）；批注台账（各节 Word 批注全量：所在章节/内容/
锚定段落——递交前逐项销号的清单）；未写章节；待拍板承诺（值仍「待补」的事项）；
校验结果（读 `work/review/check-result.json`，即第六步 `check_writing.py --json`
的落盘，未跑时空态）。**刷新口径**：服务模式路由 `/<token>/progress.html` 实时
读盘+指纹门控自刷新——页内每 30 秒探一次 `healthz` 产物指纹，变了才整页重载
（数据没变不动页面、滚动位置保留；服务断开停留最后一份有效渲染；写作过程中
agent 无需逐节刷新页面）；静态模式每节重跑 `build_review.py`。互链同款相对路径：
评审台总览「打开进度面板」入口 → 面板；面板页脚回链评审台与分析报告（服务模式
`写作进度.html`/`招标文件分析报告.html` 中文别名路由已配齐）。

## 两条使用路径

```bash
# 路径 A（默认）：本地服务直写——页面「保存」直接改 work/ 文件
python3 scripts/build_review.py --work work --pages report   # 分析阶段（G1/G2）：只产分析报告
python3 scripts/build_review.py --work work            # G3 起全量生成（评审台+报告+写作进度）
python3 scripts/serve_review.py --work work            # 起服务，打印形如下面的 URL
# [评审台服务已启动] http://127.0.0.1:62561/<token>/   （/report.html = 分析报告；/progress.html = 写作进度，自动刷新）
python3 scripts/serve_review.py --work work --status   # 用前探活（agent 每次引用前执行）
python3 scripts/serve_review.py --work work --stop     # 收尾关停（必做）
```

```bash
# 路径 B（兜底）：服务起不来（远程沙箱/用户本地打不开 localhost）→ 静态版离线流转
# 用户浏览器打开 work/review/评审台.html → 编辑 → 「导出改动文件」→ 把 JSON 发回对话
python3 scripts/apply_review.py --patch 改动文件.json --work work   # 助手代为应用
```

## 展示通道（生成即呈现；能力探测式，不硬编码平台工具）

| 环境能力 | 动作 |
|---|---|
| 有打开 URL/文件的预览类工具 | 产物落盘后**立即调用**打开 `http://…/#tab=tree` 等锚点 tab（键为英文：overview/tree/guide/promise）；写作进度面板打开 `http://…/progress.html` |
| 有内联 HTML 渲染 | 静态版页面直接给用户；提示服务模式的保存直写更顺 |
| 都没有 | markdown 链接 + 对话内结构化摘要（该有的确认门内容一样不少） |

- 单槽礼让：用户已经手动打开过某个产物/页面时，后续只发链接，不抢焦点；
- **链接形态（硬规则）**：评审台 URL 一律以 Markdown 链接发出——
  `[打开评审页面](http://…/#tab=overview)`；裸代码串不算交付（宿主普遍按 Markdown
  链接渲染可点击入口/可打开的页面卡，裸串两者都触发不了）。
- **交付即停（硬规则）**：首次起服务（或静态版首开）成功的当轮，回复以
  「页面链接 + 当前门一行指针」收束并停轮等答复，其后不得发起推进动作
  （写指引/建节/解析等）；每道门刷新同规（用户已明确授权连续模式除外）。
  首建迟于所在门（流程已推进到后面才起台）时，先补当前门的指针与停轮，再继续。
- **起服务与刷新时机：分析阶段（G1/G2）只产分析报告（`--pages report`）；
  G3 首建评审台（不带 `--pages report`）+ 写作进度面板随全量产出，G3-G6 每道门
  刷新并打开对应区**；第五步首节开写前首开进度面板（此后服务模式自刷新、静态
  模式每节重跑 build_review）；
  单轮体检（第零步）出登记表后同样只产分析报告——报告即分析结果的展示面。
  服务模式：确认服务活着（`--status`）后直接打开锚点 URL 即可（GET 实时读盘，
  刷新即最新数据）；静态离线模式：页面是生成时点快照，**每道门必须重跑
  `build_review.py` 再打开**，否则用户看到旧数据。收尾汇报时 `--stop` 关停并说明。

## 保存与应用

- 服务模式保存 = 页面自动 POST 改动数据 → `apply_review.apply_patch`：基底 sha 校验
  （页面打开后文件被外部改过则拒绝，提示重新生成）→ 写前备份 ×3（`work/review/backup/`）
  → 落盘 → 返回 diff 报告（新增/删除/改名/指引/承诺 + 下游旗标）；
- **应用成功后必做**：重跑 `python3 tender-writing/scripts/check_writing.py --guide`；把 diff 报告的
  「下游注意」逐条向用户点名；被删节点的指引行与节文件清理、新叶子补指引行按提示
  增量处理（对照 @tender-analysis/references/outline-cleanup.md 的增量走查）；**后续任何步骤引用
  目录/指引/承诺前重读对应文件**（页面保存已直写落盘，会话内旧读数作废）；
- 离线导出的改动文件走 CLI 应用时同样有基底校验与备份；用户没发就继续，不催。

## 稳定性（向用户解释服务问题时用这套口径）

- 端口由系统分配，同目录重复启动自动复用同一 URL（`--status` 可查）；
- 服务进程被杀/崩溃：数据零损失（GET 实时读盘、POST 立即落盘），页面自动降级
  离线模式（心跳 5s），未保存的编辑有 1.5s 草稿暂存（`work/review/draft.json`），
  重启服务刷新页面可恢复草稿；
- **数据新鲜度（心跳指纹比对）**：评审台 5s 心跳带产物指纹——页面打开后材料被
  外部更新（助手落盘修订 / CLI 应用改动文件）时，连接条变「材料已被助手更新 ·
  点此刷新」，点击即读到最新数据；页面有未保存编辑时文案降级为「有未保存编辑」，
  点击后确认才刷新（草稿已暂存兜底，恢复可能覆盖新写入内容）。徽标只是提示，
  不自动重载、不阻塞编辑；页面保存成功会同步新指纹，自己的保存不会误报；
- 默认空闲 2 小时自动退出（`--idle-timeout` 秒可调，0=不超时）；
- 安全口径：仅环回监听（127.0.0.1）、路径带随机 token、无网络外联、外部脚本零依赖；
  context 接口只读解析产物目录。

## 页面能力速查（回复用户时用业务说法）

- 总览：「需要你确认的事」待办卡（待拍板承诺 / 未安排章节的评分项——「去查看」
  跳报告页评分办法锚点 / 未定写法的章节，逐项带跳转按钮）；「招标文件分析报告」
  入口卡（废标/评分/待澄清数字概览 + 打开按钮；六张分析表明细全量在报告页，
  本页不重复渲染）；「写作进度」入口卡（已写 N/M 节 · 待拍板承诺数字概览 +
  打开按钮——监视面，服务模式自动刷新（数据变化才重载））；
- 目录树：拖拽（上/下插入、中间并入）、右键菜单（升级/降级/增删/改名）、撤销
  （Cmd+Z，50 步）、章节编号实时预览（合册时才套用）、树搜索、结构性修改确认条
  （增删/移动才拦，纯改名不拦）、来源徽章点击看登记原文与出处（服务模式附原文
  上下文切片）、封面/目录改删时提示合册按名识别；
- 写作指引：左树（筛选：缺素材/未分配/不在目录/待写/已写）右详情（模式切换、
  素材区间即时校验、依据原文卡、缺口四分组默认折叠——需要你提供/需要你确认/
  已从资料中找到/AI 执行说明，点击展开）；点「编辑指引」进入编辑；不在目录的行
  单独点名；**数据未生成时本 tab 整体不出现**（不渲染空态横幅）；
- 承诺清单：逐项拍板卡（说明/依据 + 你的决定），值列即时提示「要裸值」；**数据未
  生成时本 tab 整体不出现**；
- 静态离线版：「导出改动文件」按钮导出 JSON 发回对话，助手用 apply_review 应用。

## 视觉与版式（维护口径，v1.5.1 起）

- 方向 A「纸感公文体」：暖白纸面、墨色、宋体标题、细线分隔、直角（2px）、零阴影；
  唯一品牌强调色为深青，红/琥珀/绿只承担废标、待确认、已就绪三种语义。
- 模板即唯一视觉来源：令牌集中在 `templates/review-workbench.html` 的 `:root`，
  不要在规则里写裸色值；改样式只动 `<style>`，不要碰数据绑定与页面 JS。
- 品牌 logo 内联 SVG（`currentColor`，22px），不引用外部文件——`file://` 自包含是硬约束，
  两页互链同样只用相对路径文件名（`评审台.html` / `招标文件分析报告.html`），不引外部资源。
- 字号下限 11px；正文/次级/弱化文字对比度分别 ≥16:1 / 7:1 / 4.5:1（暖白底）。
- 验收三档：1440 / 1024 / 390；无横向溢出、左右 gutter 0 命中、四 tab 与溯源弹窗不破版；
  改完跑 `design-lint.mjs` 与 `listing/self_check.py`。
